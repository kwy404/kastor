SHEET 07Framework guides

kastor in your framework

Ten short, complete setups. Each one creates a single client from the driver you choose and shows one read and one write the way that framework likes them. The schema is the one from the playground in src/db/schema.ts; the Postgres client module is in Get started.

FW 01App Router, server components, server actions

#Next.js

Create the client once and reuse it across hot reloads in development, then query it from server components, server actions and route handlers. Never import the db module from a client component: the driver and your credentials must stay on the server.

Read the full guide

FW 02Nitro server routes

#Nuxt

Put the client in server/utils so Nitro auto imports it in every server route. Pages fetch through useFetch, so the database never reaches the browser bundle.

FW 03load functions and form actions

#SvelteKit

Keep the client in $lib/server so SvelteKit refuses to ship it to the browser, then read in load functions and write in form actions.

FW 04one client per process

#Express

Create the client at startup and share it. Map KastorError codes to HTTP status codes in one error middleware.

FW 05decorate the instance

#Fastify

Decorate the Fastify instance with the client and close the pool in the onClose hook so tests and graceful shutdowns finish cleanly.

FW 06a provider and dependency injection

#NestJS

Wrap the client in an injectable service. Because kastor infers types from the schema, the service exposes fully typed models without any extra classes.

FW 07Node, Bun, Deno and Workers

#Hono

Hono runs everywhere, and so does kastor. On Node use the Postgres module above; on Cloudflare Workers build the client from the D1 binding inside the request.

FW 08bun:sqlite, no driver to install

#Bun

Bun ships SQLite in the runtime. Pass a bun:sqlite Database to the sqlite adapter and you have a typed database with zero extra dependencies.

FW 09npm specifiers

#Deno

Deno imports kastor and the driver with npm: specifiers. Grant network and env access when you run it.

FW 10D1, or Postgres through a pooler

#Cloudflare Workers

Bind a D1 database in wrangler.toml and build the client per request from env.DB. D1 runs batches, not interactive transactions, so use the array form of $transaction there.

Read the full guide
