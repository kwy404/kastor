GUIDE 11Oracle ORM

An Oracle ORM in Node.js without Instant Client

kastor talks to Oracle Database through oracledb in thin mode, so a plain npm install is enough. This guide covers pools, a local FREEPDB1 container, Oracle specific types and the SQL the adapter writes for you.

#oracledb thin mode: no Instant Client required

For years, connecting Node.js to Oracle meant installing Instant Client on every developer machine, CI runner and container image. Current releases of oracledb default to thin mode, a pure JavaScript implementation of the network protocol. A normal npm install is all you need, and the same image builds on Linux, macOS and Windows.

kastor uses whatever driver instance you give it and ships no driver of its own. You create an oracledb pool and pass it to the oracle adapter from kastor/oracle. Thin mode covers ordinary application work: queries, writes, transactions, LOBs and JSON. Thick mode, enabled by calling initOracleClient(), is only needed for a short list of advanced features described in the node-oracledb documentation. kastor targets Oracle Database 19c and newer and is tested on 23ai. The adapter imports your oracledb package once to read wide NUMBER columns (bigint and decimal) as text, so no digits are lost.

#A local Oracle with FREEPDB1

The gvenzl/oracle-free images package Oracle Database Free for containers and are the usual choice for local development and CI. The command above sets the admin password and creates an application user named app. That user lives in FREEPDB1, the pluggable database that ships with Oracle Database Free.

The detail that trips people up is the service name. Oracle Database Free runs a container database with pluggable databases inside it. Your tables belong in the pluggable one, so the connect string is localhost:1521/FREEPDB1, not FREE. Connecting to the wrong service gives you ORA-01017 for a user that only exists in the PDB, or ORA-12514 when the listener does not know the service.

The first start takes a while because the database initializes its files. Follow the logs and wait for the line saying the database is ready before you run migrations. In CI, use the container health check or poll with npx kastor doctor until it succeeds.

#Create the pool and the client

Pool creation in oracledb is asynchronous, so create the pool once at startup and reuse it. The pool settings that matter most are poolMin and poolMax: keep the maximum in line with what your database user and server sessions allow.

Call await db.$disconnect() on shutdown so the pool closes its sessions. For Oracle Autonomous Database, thin mode connects with the wallet or connection string from the cloud console; the node-oracledb docs list the options, and kastor only sees the resulting pool.

#Identity columns, booleans, dates and identifier case

Oracle has a few behaviors that differ from other databases. kastor smooths over the type mapping, but some rules come from the database itself.

  • Identity columns. t.id() becomes a NUMBER(10) identity column declared GENERATED BY DEFAULT ON NULL AS IDENTITY, the native auto increment of modern Oracle releases. You do not create sequences or triggers by hand, and created rows come back with their generated id through RETURNING ... INTO out binds.
  • Booleans. kastor stores t.boolean() as NUMBER(1) with a check constraint, which works on every supported release, and the column reads and writes JavaScript true and false.
  • Dates. t.datetime() is TIMESTAMP(3) WITH TIME ZONE, so values are exact instants unaffected by the session time zone, and they come back as Date objects. t.date() is an Oracle DATE read as a 'YYYY-MM-DD' string, which avoids time zone shifts on calendar dates. Remember that Oracle DATE also carries a time of day, so ad hoc SQL comparisons on legacy DATE columns may need TRUNC.
  • Text and JSON are CLOBs. t.text() and t.json() are stored as CLOB, with an IS JSON check for json. Oracle cannot compare CLOBs directly, so equality, in, orderBy and aggregates on these columns use only their first 1000 characters. contains, startsWith and endsWith see the whole value. Use t.string(n), a VARCHAR2, for values you filter or sort by exactly.
  • Empty strings are NULL. Oracle treats '' as NULL. Writing an empty string into a required column raises ORA-01400, reported as NOT_NULL_VIOLATION. Validate input or make the column nullable.

Identifier case

Oracle folds unquoted names to upper case. kastor quotes identifiers, so a table declared as users is created as lower case "users". Application code never notices, but ad hoc SQL in SQL Developer or SQL*Plus must quote the name. If your team prefers upper case names for ad hoc work, or you map an existing schema, declare them in upper case and keep readable field names with .map().

Oracle 12.2 and newer allow identifiers of up to 128 bytes. kastor shortens generated constraint and index names that would be longer, with a stable hash suffix, so the same schema always produces the same names.

#Pagination, MERGE upserts and JSON includes

The Oracle dialect compiles the same query API you use on every other database into Oracle SQL:

  • take and skip become OFFSET ... ROWS FETCH NEXT ... ROWS ONLY, the row limiting clause of modern Oracle. Always pass orderBy with offset pagination, and use findPage for cursor pagination on large tables.
  • Writes return rows with RETURNING ... INTO out binds rather than a RETURNING result set. createMany sends one INSERT per row, because multi row VALUES needs 23ai.
  • upsert compiles to MERGE with a USING (SELECT ... FROM DUAL) source, Oracle's statement for insert or update in one step, and the row is read back with a select. Keep a unique constraint on the key and handle UNIQUE_VIOLATION if two requests may upsert the same key at the same time.
  • Nested include trees load through JSON_ARRAYAGG and JSON_OBJECT returning a CLOB, so a call with includes runs as one statement per root call rather than one per parent row.
  • Oracle foreign keys support onDelete: 'cascade' and 'set null' only. Other actions, and every onUpdate, behave as NO ACTION.
  • Filters with mode: 'insensitive' compare lower cased values, which works the same on every Oracle collation setting.

#Migrations and transactions on Oracle

Point kastor.config.ts at your schema file and at an adapter that builds the oracledb pool, as described in the API reference. Then npx kastor migrate dev --name init diffs the TypeScript schema against FREEPDB1, writes a migration file and applies it. A first migration looks roughly like this:

One Oracle rule shapes how you write migrations: every DDL statement commits implicitly. If the third statement of a migration fails, the first two stay applied. Keep migrations small, one logical change each, and test them against a copy of production data before running npx kastor migrate deploy. For an existing schema, npx kastor db pull writes the TypeScript schema from the live database, and the migrations guide covers the rest of the workflow.

Data changes are different: DML is fully transactional. db.$transaction(async (tx) => ...) runs on one pooled connection with explicit commit and rollback, and rolls back if the callback throws; outside a transaction each statement autocommits. The array form runs a fixed list of queries atomically. Oracle defaults to read committed with consistent reads, so readers never block writers. Oracle only offers read committed and serializable, so the other isolationLevel values map to the nearest stronger one. A serializable transaction raises ORA-08177 when Oracle cannot serialize it; kastor reports that as SERIALIZATION_FAILURE, and the right response is to retry the whole transaction.

#Questions people ask

Q1Do I need Oracle Instant Client to use Oracle from Node.js?

Not in thin mode, which is the default in current oracledb releases. The driver connects directly in JavaScript. Thick mode, enabled with initOracleClient(), still needs Oracle Client libraries and is only required for a few advanced features.

Q2How do I run Oracle Database locally for development?

Use the community gvenzl/oracle-free container image. Pass APP_USER and APP_USER_PASSWORD to create an application user in the FREEPDB1 pluggable database, then connect to localhost:1521/FREEPDB1.

Q3Why can I not find my table in SQL Developer?

Oracle stores unquoted names in upper case, while kastor quotes identifiers and keeps the case you wrote. A table declared as users must be queried as "users" in ad hoc SQL, or you can declare upper case names in the schema.

Q4Why does Oracle reject an empty string in a required column?

Oracle treats an empty string as NULL. Inserting '' into a NOT NULL column fails, and kastor reports it as NOT_NULL_VIOLATION. Make the column nullable or validate input before the write.

Q5How does kastor load relations on Oracle without N+1 queries?

Nested includes compile to JSON_ARRAYAGG and JSON_OBJECT subqueries returning a CLOB, so each root call runs one statement. The N+1 guide explains the approach, and the playground shows the exact SQL.
