# Notes from the sqlmore owner (MySQL, MariaDB, SQL Server, Oracle)

Requests for other owners. sqlmore works around each item until it lands.

## For core (`src/core/sql/`)

1. **Row level column expression hook.** tedious returns `DECIMAL` and
   `NUMERIC` as JS numbers, so `12345678901234567890.1234567891` comes back as
   `12345678901234567000`. Please add an optional
   `hooks.selectColumn?(expr: Sql, column: ColumnIR): Sql` and use it wherever a
   column is read into a row: `selectList`, `returningList` (OUTPUT INSERTED.x),
   `compileSelectWhere`, the IN-list loader. SQL Server would return
   `CAST(x AS NVARCHAR(60))` for decimal. Oracle could use it for `INTERVAL`
   columns. Without it, decimals on SQL Server keep about 15 significant digits.
2. **Oracle generated keys.** Oracle has no `insertId` and no bare
   `RETURNING` (only `RETURNING ... INTO :out`). Proposal: `returning: 'into'`
   makes the compiler append ` RETURNING <cols> INTO <params>` where every
   param is `hooks.outParam(column)` (an opaque marker object). The Oracle
   executor turns markers into out binds and returns the out values as rows
   (one row per affected row for UPDATE/DELETE, out binds come back as arrays).
   Until then Oracle uses `returning: 'none'`, which cannot re-select a row
   whose identity key was generated by the database.
3. **`insertDefaults` for Oracle** needs the table: Oracle has no
   `DEFAULT VALUES`, the closest is `INSERT INTO t ("id") VALUES (DEFAULT)`.
   Passing the `TableIR` as a second argument would do.
4. **`defaultRandom` on dialects without RETURNING** (MySQL, MariaDB): the row
   cannot be re-selected when a UUID primary key is generated by the
   database. Please generate `defaultRandom` values in JS before the insert
   when `hooks.returning === 'none'` (MySQL `UUID()` defaults stay in the DDL
   for raw inserts).
5. **Oracle `text` columns are CLOB**: `=`, `IN` and `ORDER BY` on a CLOB fail
   with ORA-00932. A `compareColumn?(expr, column)` hook would let Oracle
   wrap them in `DBMS_LOB.SUBSTR(x, 4000, 1)`; until then filters on `text`
   columns only work with `contains`, `startsWith`, `endsWith` and null checks
   on Oracle (documented as a limit).

## For migrate (`src/migrate/diff.ts`)

- `sameFkInDialect` renders `addForeignKey` with `{ tables: [table] }` only.
  SQL Server degrades cascading actions that would create multiple cascade
  paths (error 1785) to NO ACTION, and it needs the full schema to know.
  Please pass the full target schema there (and in `sameInDialect`) so an
  introspected `no action` key compares equal to the schema's `cascade` key
  when the dialect renders both the same way.
